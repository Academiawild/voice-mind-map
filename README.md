# Voice Mind Map

Voice Mind Map 是一个在本机打开的 AI 思考整理台。你可以输入文字、实时说话或导入完整音频；本地 FunASR 负责转写，本地 Ollama 或明确配置的在线模型提议结构化 ChangeSet，后端验证并应用后，前端自动展示变化并支持一步撤销。默认本地模式不发送内容到云端。选择在线 API 后，转写文字、当前导图和相关整理上下文会发送到配置的服务；语音识别仍在本机完成。

核心链路：

```text
文字 / 实时语音 / 音频文件
→ 本地转写
→ AI 生成 ChangeSet
→ 服务端 guard、确定性应用和完整校验
→ 工作区自动提交、展示活动并支持 undo/redo
```

当前范围是 macOS、本地单用户 Web MVP。没有账号、云同步、协作、桌面 App 或移动 App。

## 安装与启动

电脑需要：

- Node.js 22.12 或更高版本
- Python 3.11 或 3.12
- Git
- ffmpeg（只处理完整音频文件，不处理实时 PCM）
- 使用本地模型时，需要 Ollama.app 及一个已安装的本地文本模型；在线 API 模式可跳过

macOS 可通过 Homebrew 安装基础依赖：

```sh
brew install node python@3.12 git ffmpeg
```

第一次使用：

1. 双击 `install.command`。
2. 选择本地模型时，确认 Ollama 中已有 `qwen-q4kp`，或在 `.env` 将 `LOCAL_AI_MODEL` 改成其他已安装模型；选择在线服务时，按下方“在线 API”配置 `.env`。
3. 双击 `start.command`；本地模型模式会在需要时自动打开 Ollama.app。

以后只需双击 `start.command`。生产启动会先构建前端，再启动一个同时托管网页、HTTP API 和 WebSocket 的 Node 服务，以及 HTTP ASR、实时 ASR 两个 Python 子进程；生产不运行 Vite。默认网页地址是：

```text
http://127.0.0.1:8787
```

端口占用时 supervisor 会在后续 100 个端口内自动选择空闲端口，并把实际地址写入版本化 `.runtime-pids.json`。

## 音频文件大小

导入音频和录音保存不设固定文件大小上限，一次处理一个文件。仍会检查格式及空文件；现场录音至少需要 3 秒。大文件会占用更多内存和磁盘，处理时间取决于本机性能。

## 配置

本地模型配置位于根目录 `.env`：

```env
LOCAL_AI_BASE_URL=http://127.0.0.1:11434
LOCAL_AI_MODEL=qwen-q4kp
LOCAL_AI_CONTEXT=16384
```

上面是配置示例，模型名称须与本机 Ollama 已安装的模型一致。本次思考导航改版使用本机的 `huihui_ai/gemma-4-abliterated:26b` 验证；处理长篇碎片可能需要一分钟或更久。程序不会自动安装、切换模型或改写现有 `.env`。

### 在线 API（可选）

在本机 `.env` 设置 `AI_PROVIDER=api`、`REMOTE_AI_BASE_URL`、`REMOTE_AI_MODEL` 和 `REMOTE_AI_API_KEY`，然后重启。基础地址填写兼容 Chat Completions 的 HTTPS 地址（例如 `https://sidrune.ai/v1`）。不要把密钥放入源码、前端、截图或提交到 GitHub。

当前用户选择的在线模型为 `claude-opus-5-5`，两个处理阶段暂时统一使用它；尚未启用 Sonnet 分流。网页服务状态会区分在线 AI 与本地 AI。在线模式不依赖 Ollama；FunASR 和 ffmpeg 仍用于本地语音处理。切回 `AI_PROVIDER=ollama` 即恢复原有本地模型配置。

配置在线 API 不会自动实现边说边生成导图：当前仍是实时转写、结束录音后整理导图。

## 工作区交互

- 默认是“思路”桌面：可读字号的主题卡片、嵌套念头和全文查找；最上方突出一个有理由的下一步，其他入口可以切换。“我来想一想”把问题带入草稿，“一起推演”让当前配置的 AI 继续分析。
- “思路 / 导图”切换阅读方式，使用同一份文档；搜索词、阅读位置、选中的切入点和连线说明开关会在本次页面内保留。右栏分别记住全图、各念头和不同视角的阅读位置。顶部“排个先后 / 大胆联想 / 挑战一下”直接启动对应思考。
- 顶栏：导图标题、节点数、undo/redo、显示全图、服务状态和更多菜单。
- 底部捕捉条：文字输入、`Cmd+Enter` 整理、实时录音、完整音频导入和当前处理阶段。
- 右侧思考导航：思路视角优先展示联系和选中念头，导图视角额外展示最多三个切入点。跨分支联系显示解释，推测标为“联想”（画布使用虚线）。支持继续推演和纠正联系。本次变更和原始输入收进记录，原话可一键带回输入框。
- 节点支持“想清楚了 / 做完了”“先放一放”和恢复。已完成、暂放的节点及其子树退出当前推荐，但内容和原推荐不删除；可撤销，也随文档保存。
- 点击节点：突出直接相关的节点与连线，输入框显示当前讨论对象；“回到全图”解除局部讨论。可编辑标题/正文、展开 AI 联想或删除非根分支。
- 画布：普通分支可以折叠；“只看主题 / 展开全图”切换总览并调整视角。连线说明默认按选中节点显示，也可手动显示全部说明。导航选择会展开目标路径，不自动移动视角。
- 整理期间显示已用时间并支持取消；此时仍可写下新念头，旧请求完成不会清空新草稿。取消会中止浏览器及后端发给本地模型的请求，阻止迟到结果应用和后续修复重试。
- 整理失败后可直接“重试上次整理”：沿用上次输入和讨论对象，不重复保存原话、不清空后来写的新草稿。导入音频转写失败后也可重试原文件；重试信息只在当前页面内保留。
- 输入框随文字自动增高，长笔记不再挤在一行里。
- `Cmd+Z` / `Cmd+Shift+Z`：操作最多 30 步工作区历史；输入框内保留系统原生文本撤销。
- “更多”菜单：导出 JSON、导出 Markdown，或关闭本次本地运行。

AI 结果自动应用。新增、修改、移动和删除会显示在活动栏；撤销不会重置用户当前画布视角。实时 ASR 的 partial 文字只显示在捕捉条，不会写入正式导图。

## 本地数据

- 识别成功的录音、转写和元数据：`outputs/`。
- 新捕捉日志：`.runtime/capture-journal-v2.json`。
- 当前导图、坐标、视角、推测展开状态、思考入口、原始输入、草稿及已提交录音 ID：浏览器键 `voice-mind-map:workspace:v2`，兼容原有 V2 数据。
- 运行实例记录：`.runtime-pids.json`。

旧 `outputs/` 内容不会删除，也不会迁移进新捕捉索引。新版本不读取或删除旧浏览器 key。undo 历史、处理进度和浮层状态不会持久化。

原始文字与已成功转写的原文在发起整理前进入输入记录，撤销导图不会撤销原话；程序生成的“换个入口”等指令不记作用户原话。当前文字记录保存在该浏览器、该站点的本地存储中，并不是磁盘备份；清理站点数据会丢失这些文字记录。存储失败会明确提示。普通分支折叠状态只在本次页面内保留。

录音的导图提交和服务端“已整理”标记分别处理：标记失败只重试标记，已提交 ID 随工作区保存，避免刷新后重复调用 AI。此机制不提供多标签页并发协调。

## 常见问题

### 语音按钮一直显示加载中

CPU 冷启动通常需要约 60–90 秒。可运行 `npm run doctor` 检查 Python、FunASR 和 ffmpeg；HTTP ASR 与实时 ASR 会独立上报状态。

### 实时识别中断

录音期间浏览器保留完整 MediaRecorder Blob。结束后先停止采集，再等待整段录音的收尾确认（最多 8 秒）；分段识别结果不视为整段结束。实时链路中断或未收到收尾确认时，同一个完整 Blob 会进入 `/api/transcription/file` 做 HTTP fallback；两条服务链不会混用，实时 PCM 永远不会送入 ffmpeg。录音过程中另写的草稿不会被识别结果覆盖。

### 页面能打开但不能整理

运行 `npm run doctor`，确认 Ollama 正在运行且 `LOCAL_AI_MODEL` 对应的模型已经安装。模型返回无效 JSON 或不符合 ChangeSet schema 时只会低温修复一次；再次失败会返回结构化错误，不会退回旧协议或整树 fallback。

### 如何安全关闭

在顶栏“更多”菜单选择“关闭本次运行”。关闭器只处理 manifest 中属于当前 runtimeId、项目目录和命令标识的受管进程。
